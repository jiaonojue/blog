## 术语速查（先扫一眼，后面就不啰嗦了）

| 词 | 白话解释 |
|---|---|
| **框架** | 搭页面用的工具箱，决定文件怎么组织、页面怎么生成 |
| **静态站** | 提前把页面"烤"成 HTML 文件，访客打开时不需要服务器现场计算。快、便宜、几乎不会崩 |
| **构建** | 把源码"编译"成能上线的成品文件的过程，通常一条命令 |
| **组件** | 可反复使用的一块界面，比如按钮、卡片、导航条 |
| **设计令牌** | 把颜色、字号、间距、圆角写成一份"配方"集中管理，改一处全站生效 |
| **CI/CD** | 每次提交代码，机器自动帮你构建、检查、发布 |
| **GitHub Actions** | GitHub 自带的机器人流水线，CI/CD 的具体实现，免费额度对个人站绰绰有余 |
| **PR（Pull Request）** | 把改动"申请合并"进主分支，合并前可检查、可放弃，是一道安全阀 |
| **SEO** | 让搜索引擎能读懂、收录、正确展示你的页面 |
| **OG 图** | 分享到微信/QQ/X 时显示的那张预览卡片 |
| **RSS** | 一种订阅格式，读者用阅读器就能追更，不用天天来你网站看 |
| **字体子集化** | 中文字体动辄 5–10MB，只保留页面实际用到的字，体积能降到几十分之一 |
| **懒加载** | 图片滚动到眼前才开始下载，首屏更快 |
| **无障碍（a11y）** | 让键盘用户、读屏软件用户也能正常使用，也是素养 |
| **CDN** | 分布在全球的缓存节点，让各地打开都快 |
| **Git LFS** | Git 的大文件扩展，专门存图片、视频这类大文件 |
| **base path** | 网站放在子路径（如 `/repo/`）时，所有资源路径都要加前缀，配错就整站白屏——新手第一大坑 |

## 一、灵魂与定位（Q1–Q12）

**Q1｜网站的第一身份是什么？** — 访客 3 秒内会给你归类，这个归类由它决定；首页文案、导航顺序、留白比例全都跟着它走。选错会出现"看着像作品集，点进去全是日记"的割裂感。
- A. 个人名片：让人快速知道你是谁、在做什么 — 优点是清楚，缺点是"和领英没区别"
- B. 创作档案：作品/项目优先，像一本可浏览的作品集 — 有实物最抓人，但要求你真有作品
- C. 长期博客：文章与思考为主，网站是一本"刊物" — 最有生命力，但要求持续写
- D. 不知道，你替我定
▸ 倾向 B——有实物最抓人，名片信息放首屏即可。

**Q2｜主要给谁看？** — 人群决定语气、信息密度、专业度。给招聘者看要成果和数据，给同好看看要共鸣和梗，两者写法几乎相反。
- A. 招聘者、合作方：要可信、有成果 — 但容易写得像简历，没人愿意读完
- B. 同好、二次元朋友：要有趣、有共鸣 — 但可能让专业读者觉得"不够正经"
- C. 未来的自己：像一本公开日记 — 最真诚，但最不讨陌生人喜欢
- D. 不知道，你替我定
▸ 倾向 A+B——先让人信任，再让人喜欢你。

**Q3｜访客离开时，最该记住的一件事？** — 这是全站唯一的设计主线。每个页面、每个动效都要为它服务；想同时记住三件事，结果是一件事都记不住。
- A. 视觉真好看：审美即名片 — 传播力最强，但"好看"是最容易过时的资产
- B. 这人专业可靠：能力即名片 — 最实用，但纯靠排版很难让人眼前一亮
- C. 这人有个有趣的灵魂：人格即名片 — 最难忘，但最难做，且依赖内容
- D. 不知道，你替我定
▸ 倾向 A——二次元站的第一优势就是视觉，但用 B 兜住可信度。

**Q4｜网站的语气？** — 它会渗透到文案、按钮文字、404 页、报错提示。语气不统一，比视觉不统一更让人觉得"廉价"。
- A. 克制高级：少说话，让作品说话 — 高级，但对内容质量要求极高，空页面会很尴尬
- B. 元气亲切：像朋友带你参观他的房间 — 亲和力强，风险是滑向"幼稚"
- C. 中二戏剧化：有设定、有台词、有世界观 — 记忆点最强，但用久了容易腻，且排斥非同好
- D. 不知道，你替我定
▸ 倾向 B，局部放一点 C——亲切是底色，中二是调味。

**Q5｜要不要"角色化"？** — 决定你的视觉投资方向：是投资一个 IP（角色、立绘、表情），还是投资排版与摄影。两者都很贵，但贵在不同地方。
- A. 真实的我：真名/常用 ID、真实经历 — 信任成本最低，但视觉上最难做出差异
- B. 虚拟形象/IP：一个固定角色代表你 — 视觉统一、可长期积累，但要维护设定
- C. 半虚构：角色是外壳，信息是真的 — 兼顾两者，但边界要写清楚，否则显得不诚实
- D. 不知道，你替我定
▸ 倾向 B——视觉和语气容易统一，真实信息放关于页。

**Q6｜内容主线是什么？** — 决定首页推荐什么模块、导航留几项、以及你未来一年会写什么。它也是你"写不出来"时唯一能救你的东西。
- A. 技术/学习：笔记、项目、踩坑 — 专业感强，但同类内容极多，很难脱颖而出
- B. 生活/随笔：日常、旅行、思考 — 最有人味，但需要文笔
- C. 二次元安利：番剧、音乐、游戏、收藏 — 最能暴露品味、最容易引发"我也是"，但受众窄
- D. 不知道，你替我定
▸ 倾向 A+C 双主线——一个证明能力，一个暴露品味。

**Q7｜更新节奏？** — 决定要不要博客系统、要不要评论、要不要接 CMS。承诺了高频却做不到，比一开始就低频更伤。
- A. 高频轻量：一周多条短内容 — 站点显得"活"，但极耗精力，且容易变成流水账
- B. 低频长文：一月一两篇，但每篇都值得读 — 可持续，但要求每篇质量高
- C. 一次性作品集：建好就基本不动 — 最省心，但会慢慢"过期"
- D. 不知道，你替我定
▸ 倾向 B——对个人站最可持续，也不容易"开天窗"。

**Q8｜隐私边界？** — 信息一旦上网就收不回，还会被爬虫抓走。它也决定你要不要做"联系表单"（表单意味着你要处理别人的信息）。
- A. 只留昵称 + 邮箱：最低暴露 — 安全，但显得疏离
- B. 公开社交账号：方便找到你 — 平衡，但可能被骚扰
- C. 详细资料：城市、学校、经历都写 — 最可信，但风险最高、最难撤回
- D. 不知道，你替我定
▸ 倾向 A——个人站的安全感来自"可联系但不可追踪"。

**Q9｜语言？** — 每多一种语言，就要多维护一份文案，而且是长期成本。双语最怕的是"英文版永远停在两年前"。
- A. 纯中文 — 维护最轻，但放弃了海外读者
- B. 中英双语：中文为主，关键页有英文 — 性价比最高，但要有纪律
- C. 中日英三语：面向二次元同好 — 受众最广，但维护成本三倍
- D. 不知道，你替我定
▸ 倾向 B——英文摘要就够，别让翻译拖垮更新。

**Q10｜怎样算"这个站成功了"？** — 决定你优化什么。追停留时长、追转化、追自我满意，是三条完全不同的路。
- A. 访客愿意停留、多点几页 — 可测量，但容易为了数据堆内容
- B. 有人通过它联系你、给你机会 — 最实际，但会把站做成"简历"
- C. 你自己每次打开都觉得满意 — 最持久，但无法量化
- D. 不知道，你替我定
▸ 倾向 C——个人站的终极指标是自洽，其他都是副产品。

**Q11｜你打算参与到什么程度？** — 直接决定代码要多"傻瓜化"：注释密度、内容格式、是否要图形化后台。
- A. 完全交给 agent，我只验收 — 最省事，但你将无法判断它做得对不对
- B. 我会改文字、换图片，但不碰代码 — 最现实，所以内容必须和代码彻底分离
- C. 我愿意学着改一点代码 — 上限最高，但要花时间
- D. 不知道，你替我定
▸ 倾向 B——目录、注释、内容格式必须对人类友好。

**Q12｜交付节奏？** — 视觉项目最大的浪费是"全做完才发现方向不对"。分阶段验收，是唯一能低成本纠错的办法。
- A. 一次成型：几天内全部做完 — 最快看到成品，但返工最贵
- B. 三阶段：骨架 → 视觉 → 内容，每阶段验收 — 最稳，但需要你多次参与
- C. 先最小可用，再长期迭代 — 最灵活，但容易永远停在"半成品"
- D. 不知道，你替我定
▸ 倾向 B——视觉项目最怕一口气做完才发现方向不对。

> 本区私心组合：**创作档案 + 亲切语气 + 半虚构角色 + 低频长文 + 三阶段交付**。

## 二、美术与视觉（Q13–Q32）

**Q13｜主风格选哪一支？** — 全站气质的源头。它一旦定了，字体、圆角、动效、插画全都要向它对齐；中途换风格等于重做。
- A. 日系清新：透明感、天空、光影、留白 — 耐看、阅读友好，但"惊艳度"要靠单张大图撑
- B. 赛博霓虹：深色底、荧光色、故障与扫描线 — 第一眼冲击最强，但久看疲劳、暗色阅读体验差
- C. 漫画分格：粗描边、网点纸、对话框 — 辨识度最高，但实现难度大，容易做成"廉价漫画"
- D. 不知道，你替我定
▸ 倾向 A 打底，用 C 的分格语言做首页——耐看，又有辨识度。

**Q14｜主色？** — 全站不超过三色是铁律：颜色越多，越像模板。主色会出现在按钮、链接、强调、选中态上，用得最多也最容易被看腻。
- A. 天空蓝 + 白：干净、通透 — 安全、专业，但略显"通用"
- B. 樱粉 + 奶油：柔软、亲近 — 亲和力强，但极易滑向"廉价可爱"
- C. 墨黑 + 一点荧光（红或青）：强烈、设计感 — 最有海报感，但容错率低
- D. 不知道，你替我定
▸ 倾向 A，粉色只做点缀。

**Q15｜明暗模式？** — 暗色模式不是"把颜色反过来"，而是要重新调一遍对比度和阴影，工作量约等于再做半套视觉。
- A. 亮色为主：清爽，适合阅读 — 成本最低，但夜间用户不友好
- B. 暗色为主：氛围强，适合霓虹风 — 氛围最好，但长文阅读疲劳
- C. 双模式可切换：两边都要 — 体验最好，但视觉工作量 +50%
- D. 不知道，你替我定
▸ 倾向 C，默认亮色——暗色是加分项，不是必答题。

**Q16｜色彩浓度？** — 饱和度直接决定"高级还是廉价"。高饱和在手机上刺眼，在低端屏上发灰，是双输。
- A. 高饱和明快：二次元感强 — 一眼就"二次元"，但刺眼、易腻
- B. 低饱和莫兰迪：高级、耐看 — 质感好，但可能"不够二次元"
- C. 高对比黑白 + 一点色：最有海报感 — 最出效果，但要求排版功力
- D. 不知道，你替我定
▸ 倾向 C——黑白灰做骨架，一个强调色负责"眼前一亮"。

**Q17｜中文字体？** — 中文排版是气质的半条命。中文字体文件大、字形差异大，正文用错字体，读三行就累。
- A. 思源黑体/更纱黑：干净、现代 — 界面最稳，但"没有性格"
- B. 霞鹜文楷：有手写温度 — 有温度，但长文密度低、小字号发糊
- C. 站酷/得意黑等个性字：标题很抢眼 — 抢眼，但排长文是灾难
- D. 不知道，你替我定
▸ 倾向 A 做正文，B 做引用/签名——别用个性字排长文。

**Q18｜标题字体气质？** — 标题是"第一印象的字体"，它决定你像杂志、像手账、还是像游戏。
- A. 明朝/宋体：文艺、有文学感 — 气质最好，但小字号发虚
- B. 手写/马克笔：亲切、像手账 — 有人味，但大量使用会失控
- C. 粗黑/像素：有力量，或复古游戏感 — 冲击力强，但容易显得"土"
- D. 不知道，你替我定
▸ 倾向 A——和"创作档案"的定位最搭。

**Q19｜英文与数字字体？** — 小字号英文和数字最容易暴露品味：日期、页码、标签、代码，全是它。
- A. Inter/系统字体：稳，不出错 — 安全，但没有个性
- B. Space Grotesk：几何感，有个性 — 细节加分，但要搭配得当
- C. 等宽字体：技术感、极客感 — 极客味足，但大段英文会难读
- D. 不知道，你替我定
▸ 倾向 B——小字号英文最容易暴露品味。

**Q20｜插画从哪来？** — 这是全站最值得花钱的地方，也是"眼前一亮"的真正来源。一张好图，胜过十个动效。
- A. 自己画：独一无二 — 最独特，但周期以周计，且风格可能不稳定
- B. AI 生成：快 — 最快，但风格难统一、版权边界模糊、容易被识破
- C. 委托画师/购买商用素材：唯一性和版权都清晰 — 最稳，但要花钱、要等档期
- D. 不知道，你替我定
▸ 倾向 C——一张高质量主视觉，胜过十张凑数的图。

**Q21｜要不要一个固定角色？** — 角色是"可积累的资产"：用得越久越值钱，也是别人记住你的最短路径。
- A. 原创角色：长期资产 — 回报最高，但要设定、要画、要维护
- B. 用现有头像/自画像：低成本 — 便宜，但撑不起"IP"
- C. 不要角色：纯排版路线 — 最干净，但放弃了二次元最强的表达手段
- D. 不知道，你替我定
▸ 倾向 A——哪怕只是一个剪影，也能成为站的"脸"。

**Q22｜角色怎么出现？** — 出现频率决定她是"惊喜"还是"噪音"。常驻角色看三次就腻，偶尔出现会被截图。
- A. 常驻看板娘：每页都在 — 存在感最强，但极易腻，还挡内容
- B. 只在关于页/特定页：有登场感 — 最舒服，但浪费了角色的引流能力
- C. 只做彩蛋：偶尔遇见 — 最有惊喜，但大部分人看不到
- D. 不知道，你替我定
▸ 倾向 B——常驻会腻，彩蛋会惊喜。

**Q23｜背景怎么处理？** — 背景是性能杀手第一名。粒子、星空、樱花雨，在低端手机上会直接掉帧。
- A. 纯色 + 微纹理：稳、快、阅读友好 — 最稳，但需要靠别处出彩
- B. 渐变光晕：氛围感强 — 氛围好，但容易撞脸一堆 AI 站
- C. 星空/樱花/粒子：动起来很梦幻 — 最梦幻，但吃性能、吃电量
- D. 不知道，你替我定
▸ 倾向 A，首屏单独放一张大图——把"惊艳"集中在一个位置。

**Q24｜反复出现的装饰母题？** — 统一感来自"重复同一个元素"，不是"堆很多元素"。母题是让十个页面看起来像一个设计的粘合剂。
- A. 樱花、星星、四角星 — 最直观的二次元符号，但用得最滥
- B. 对话框、贴纸、胶带、便签 — 有手账/漫画的叙事感，比纯装饰耐看
- C. 网格、准星、UI 边框、编号 — 最"设计感"，但偏冷、偏硬
- D. 不知道，你替我定
▸ 倾向 B——有叙事感，比纯装饰更耐看。

**Q25｜卡片形状？** — 圆角大小是气质的开关：越圆越软、越亲和；越方越冷、越编辑感。
- A. 大圆角软糖感：亲切 — 亲和，但容易"可爱过头"
- B. 直角杂志感：冷静、编辑感 — 高级，但显得疏离
- C. 斜切/分格：漫画感强 — 有辨识度，但布局难度高
- D. 不知道，你替我定
▸ 倾向 A——圆角和二次元的柔软气质同源。

**Q26｜边框与描边？** — 描边粗细决定"是 UI 还是插画"。全站粗描边会显得吵，局部粗描边会显得用心。
- A. 无边框 + 柔和阴影：现代 — 干净，但缺少个性
- B. 1px 细线：克制、精确 — 精致，但显得"日式极简"，不够二次元
- C. 2–3px 粗描边：漫画感、贴纸感 — 最出效果，但用多了会吵
- D. 不知道，你替我定
▸ 倾向 C，但只用于图片和重点卡片。

**Q27｜鼠标指针？** — 最小的成本、最大的"细节感"。访客一天要看成百次，改动它的性价比极高。
- A. 系统默认 — 零风险，但也零印象
- B. 自定义小图标（星、箭头、笔尖） — 性价比最高，但要处理点击态
- C. 和角色相关（比如角色的小手） — 最有趣，但可能影响精准点击
- D. 不知道，你替我定
▸ 倾向 B——最小成本的高级细节。

**Q28｜加载页？** — 加载页是"用动画掩盖等待"。但静态站本来就快，加了反而制造等待。
- A. 极简进度条/百分比 — 有仪式感，但人为延长了 1–2 秒
- B. 角色小动画 — 最有记忆点，但每次访问都要看，第三次就烦
- C. 不要，直接进 — 最快，但少了"开场"
- D. 不知道，你替我定
▸ 倾向 C——静态站本来就快，加载页是给自己加戏。

**Q29｜404 页？** — 这是访客最可能记住的"计划外页面"，也是最容易做出人格感的地方。
- A. 幽默插画 + 一句吐槽 — 最讨喜，成本也低
- B. 一个小游戏/互动 — 最惊艳，但开发成本高
- C. 极简"迷路了" — 最克制，但浪费了一次露脸机会
- D. 不知道，你替我定
▸ 倾向 A——404 是最容易被截图传播的页面。

**Q30｜站点图标（favicon）？** — 浏览器标签页上的那张小图，是全天候挂在用户屏幕上的品牌。
- A. 字母/符号 — 最省事，但毫无记忆点
- B. 角色头像 — 最有辨识度，但小尺寸下容易糊
- C. 手绘小图 — 有个性，但要求画得够简洁
- D. 不知道，你替我定
▸ 倾向 B——最便宜的 branding。

**Q31｜质感？** — 纯数字画面有"塑料感"，加一点颗粒能立刻脱离模板味。
- A. 干净数码感 — 现代，但容易撞脸模板
- B. 纸张噪点/颗粒：像印出来的 — 质感最强，成本极低，但要控制在 3%–5%
- C. 半调网点/印刷错位：漫画印刷感 — 最有味道，但容易过头
- D. 不知道，你替我定
▸ 倾向 B，透明度 3%–5%。

**Q32｜"克制线"画在哪？** — 二次元站成败的关键：全站热闹＝没有重点；全站干净＝不够二次元。这条线决定你能不能同时做到"眼前一亮"和"待得住"。
- A. 全站都干净，靠一张主视觉撑场 — 最安全，但除了首屏都平淡
- B. 全站都热闹，走到哪都有戏 — 最"二次元"，但读三篇文章就累
- C. 分区处理：首页热闹，文章页绝对安静 — 唯一能两者兼得的解，但要求纪律
- D. 不知道，你替我定
▸ 倾向 C——这是"眼前一亮"和"待得住"能共存的唯一解。

## 三、信息架构与页面（Q33–Q52）

**Q33｜单页还是多页？** — 决定网站是"一张海报"还是"一本书"。单页冲击力强但装不下内容，多页能装但首页容易平庸。
- A. 单页滚动：像一张长海报 — 冲击力最强，但内容一多就变成"无限滚动地狱"
- B. 多页：每个主题一个页面 — 最能装，但首页容易变成"目录"
- C. 混合：首页单页叙事 + 子页承载内容 — 两者兼得，但架构复杂度上升
- D. 不知道，你替我定
▸ 倾向 C——首页负责"惊艳"，子页负责"archive"。

**Q34｜首页第一屏放什么？** — 这是全站最重要的一块屏幕。访客在这里决定"留下还是关掉"。
- A. 大字标题 + 一句话自我介绍 — 最清楚，但最不像二次元
- B. 角色主视觉 + 导航 — 最惊艳，但可能"好看但不知道你是谁"
- C. 最新作品/最新文章 — 最实用，但第一眼不够抓人
- D. 不知道，你替我定
▸ 倾向 B，但必须叠一句话和两个明确按钮——美，且知道往哪点。

**Q35｜导航形式？** — 导航决定"逛起来顺不顺"。形式要服从视觉语言，否则会像贴上去的。
- A. 顶部固定栏 — 最常规、最不会错，但也最没记忆点
- B. 侧边栏 — 适合内容多的站，但挤占阅读宽度
- C. 悬浮胶囊/底部 Dock — 轻，和"贴纸/胶囊"的语言一致，但移动端要小心遮挡
- D. 不知道，你替我定
▸ 倾向 C——轻，且和视觉语言一致。

**Q36｜页面清单要多大？** — 每多一个页面，就多一份维护和一份"空页面"风险。空页面比没有更尴尬。
- A. 极简三页：首页、关于、联系 — 最省心，但撑不起"作品集"
- B. 标准六页：+ 作品、博客、友链 — 平衡，够用两三年
- C. 全能十页：+ 收藏、相册、Now、工具箱 — 最丰富，但一半会长期空着
- D. 不知道，你替我定
▸ 倾向 B 起步，架构上留好扩展位。

**Q37｜关于页怎么写？** — 关于页是访客最想看、也最容易写砸的一页。自述最容易变成流水账。
- A. 一段话：短、克制 — 最省事，但信息量少
- B. 时间线：经历一目了然 — 最清楚，但很像简历
- C. 问答体：像采访 — 最好读、最有性格，但需要设计问题
- D. 不知道，你替我定
▸ 倾向 C——"Q：你是谁？A：……"比简历式自述动人得多。

**Q38｜作品集怎么组织？** — 卡片只证明"你做过"，案例长页才证明"你会做"。
- A. 网格卡片：快速浏览 — 浏览效率高，但说服力弱
- B. 案例长页：讲背景、过程、结果 — 最有说服力，但每篇都要写很久
- C. 分类 + 筛选：作品多了以后友好 — 适合量大，但个人站通常用不上
- D. 不知道，你替我定
▸ 倾向 B——讲过程才显专业，卡片只当索引。

**Q39｜博客列表？** — 列表页决定"有没有人点进去"。它也是被搜索引擎抓取的主要入口。
- A. 传统列表：标题 + 日期 + 摘要 — 最耐看、最易被搜索，但不够"设计感"
- B. 卡片瀑布 — 好看，但信息密度低、加载慢
- C. 时间轴 — 有叙事感，但条数一多就失控
- D. 不知道，你替我定
▸ 倾向 A——列表最耐看，也最容易被搜索到。

**Q40｜文章页排版？** — 文章页是"待得最久"的页面。这里的唯一目标是不打扰。
- A. 单栏，最大宽度约 680px — 最舒服，但长文缺导航
- B. 单栏 + 侧边目录 — 长文友好，目录本身就是"专业感"
- C. 杂志式：图片出血、引文跨栏 — 最惊艳，但排版工作量翻倍
- D. 不知道，你替我定
▸ 倾向 B。

**Q41｜要不要"收藏/安利"页？** — 喜欢的番、音乐、游戏。这是访客最可能产生"我也是！"的地方，也是人格感最强的一页。
- A. 要 — 人格感最强，但需要持续维护
- B. 不要：保持聚焦 — 最聚焦，但放弃了最强的共鸣点
- C. 以后再加 — 折中，但"以后"通常不会来
- D. 不知道，你替我定
▸ 倾向 A。

**Q42｜友链页？** — 友链是"社交证明"。没有真实友链时，空页面比没有更尴尬。
- A. 要 — 有社区感，但需要真的有人换
- B. 不要 — 干净，但少了互推渠道
- C. 以后再说 — 现实，但可能一直空着
- D. 不知道，你替我定
▸ 倾向 C。

**Q43｜评论系统？** — 静态站没有后端，评论必须借第三方（Giscus 基于 GitHub Discussions，免费）。没人评论的评论区，比没有评论区更伤士气。
- A. 要：Giscus — 免费、干净、和 GitHub 天然契合，但要求访客有 GitHub 账号
- B. 初期不要：留好接口 — 最稳，随时能加
- C. 只放一个留言板 — 门槛低，但容易变成垃圾场
- D. 不知道，你替我定

**Q44｜联系方式怎么放？** — 图标负责"找到你"，邮箱负责"真的联系上"。只放图标，很多人不会去点。
- A. 邮箱 — 最直接，但会招来垃圾邮件
- B. 社交图标（GitHub、B站、X 等） — 最自然，但转化率低
- C. 表单 — 最"专业"，但静态站要接第三方服务
- D. 不知道，你替我定

**Q45｜简历？** — 网页给体验，PDF 给 HR。两者受众不同，别指望一个顶两个。
- A. 在线简历页 — 体验最好，但 HR 没法存档转发
- B. PDF 下载 — 最实用，但和网站视觉脱节
- C. 不做 — 最干净，但可能错过机会
- D. 不知道，你替我定
▸ 倾向 A+B。

**Q46｜音乐播放器？** — 自动播放会被浏览器拦截，版权也是雷区。歌单页比播放器更体面。
- A. 全局悬浮播放器 — 氛围最强，但挡内容、耗电、版权风险
- B. 只在某一页 — 折中，但用户要主动去找
- C. 不做，或只做一张"歌单页" — 最体面，零风险
- D. 不知道，你替我定

**Q47｜相册/画廊？** — 图片一多，性能和版权都会变成负担，而且会稀释主线。
- A. 要 — 视觉最丰富，但最吃性能
- B. 不要 — 最轻，但少了"生活感"
- C. 以后 — 现实
- D. 不知道，你替我定
▸ 倾向 C。

**Q48｜Now 页？** — 一页写"我最近在做什么"。更新成本极低，却能让静态站"活着"。
- A. 要 — 性价比最高的"活人感"
- B. 不要 — 少一个要维护的页面
- C. 以后 — 现实
- D. 不知道，你替我定

**Q49｜工具箱/资源页？** — 除非你真有独特资源，否则容易变成链接垃圾场。
- A. 要 — 有实用价值，但需要持续筛选
- B. 不要 — 最聚焦

- D. 不知道，你替我定

**Q50｜文章 URL 结构？** — URL 一旦发布就很难改（外链、搜索收录都会断）。这是"现在花一分钟，以后省一天"的决定。
- A. `/blog/文章名` — 短、稳、换框架也不用改
- B. `/posts/2026/文章名` — 有归档感，但地址长

**Q51｜需不需要面包屑/返回？** — 小站层级浅，面包屑通常是多余装饰。
- A. 面包屑 — 层级清晰，但小站用不上

- D. 不知道，你替我定

## 四、交互与动效（Q53–Q68）

**Q53｜页面转场？** — 转场的第一美德是"不耽误事"。炫技型转场第一次惊艳，第五次让人烦。

- B. 滑动：有方向感 — 有空间感，但每次都要等
- C. 漫画分格遮罩：很惊艳 — 最惊艳，也最容易腻
- D. 不知道，你替我定

**Q54｜滚动动画强度？** — 滚动动画负责"呼吸感"。但每个区块都动，等于没有重点，还会拖慢低端设备。

- B. 轻：淡入 + 上移 12px — 有呼吸感，不抢内容
- C. 强：每个区块都有独立动作 — 最"设计感"，但最吵
- D. 不知道，你替我定
▸ 倾向 B。

**Q55｜视差滚动？** — 背景和前景以不同速度移动，制造纵深。只在首屏用，是"舞台感"；全站用，是"晕车"。
- A. 要，全站 — 纵深感最强，但最容易晕、最吃性能
- B. 不要 — 最稳
- C. 只在首屏 — 舞台是舞台，书房是书房
- D. 不知道，你替我定

**Q56｜鼠标跟随光斑/粒子？** — 桌面端的"高级感开关"。移动端没有鼠标，为它付出性能是纯亏。
- A. 要 — 桌面很加分，但移动端白费
- B. 不要 — 最省
- C. 仅桌面端 — 性价比最高
- D. 不知道，你替我定

**Q57｜悬停微交互？** — 鼠标悬停时的反馈，是"这站很用心"的直接来源。
- A. 位移/放大 — 最简单，但很"模板"
- B. 发光/描边绘制 — 和手绘/漫画语言最搭

- D. 不知道，你替我定

**Q59｜打字机效果？** — 逐字出现的动画。只在第一句话上用是仪式感，用多了是折磨。

- B. 多处使用 — 到处都在"打字"，阅读被打断
- C. 不要 — 最干净
- D. 不知道，你替我定

**Q60｜光标拖尾？** — "新鲜三秒、烦躁三分钟"的典型。它会持续干扰阅读。

- B. 不要 — 最稳
- C. 可开关 — 折中，但没人会去关
- D. 不知道，你替我定

**Q61｜音效？** — 声音必须是访客主动要的。默认出声，是最快失去访客的方式。

**Q62｜背景音乐？** — 浏览器本来就会拦截自动播放，所以"默认开"基本是伪选项。

**Q67｜整体交互密度？** — "适度"最难，也最高级。安静到热闹之间，有一个刚刚好的位置。

## 五、技术栈与架构（Q69–Q89）

**Q69｜前端框架选哪个？** — 框架＝搭页面的工具箱。它决定页面怎么生成、打开多快、以及 agent 改代码时有多容易改错。你的站是"内容型静态站"，选重型框架会又慢又难维护。

- B. CSS Modules：样式和组件一一对应 — 结构最清晰；代价是写起来慢，容易各写各的
- C. UnoCSS：更轻更快 — 性能好，但生态和资料少

## 你会拿到什么

一份可直接粘贴给 agent 的目标提示词，八个部分：

1. **项目定位与验收标准**——什么算"做完了、做对了"
2. **视觉规范**——色板、字体、母题、圆角/阴影、动效原则（含具体数值）
3. **页面与组件清单**——每页有什么、每个组件长什么样
4. **技术栈与目录树**——精确到文件夹和文件职责
5. **内容模型与写作流**——一篇文章从写到发布要经过什么
6. **部署流水线与回滚**——Actions 怎么配、坏了怎么退
7. **分阶段任务**——每阶段的产出物和验收点
8. **禁止事项**——自动播放、过度动效、无版权素材、彩虹渐变等
