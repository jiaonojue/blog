## 零、先记住三个命令

打开终端（在项目文件夹里，右键 → Git Bash Here），只需要记三个：

| 命令            | 什么时候用                 | 会发生什么                                     |
| --------------- | -------------------------- | ---------------------------------------------- |
| `npm run dev`   | **写东西的时候一直开着**   | 启动本地预览。改文件保存后浏览器自动刷新       |
| `npm run check` | **每次提交到 GitHub 之前** | 逐项检查：密钥 → 类型 → 代码风格 → 构建 → 图片 |
| `npm run build` | 一般不用手动跑             | 生成最终的 `dist/` 目录（GitHub 会自动跑）     |

`npm run dev` 跑起来后，浏览器打开 **http://127.0.0.1:5178/blog/** 就能看到网站。
**不要关那个终端窗口**，关了预览就断了。想停就按 `Ctrl + C`。

> **注意**：本地预览的地址末尾有 `/blog/`。这是仓库名，不是笔误。

## 1. 改站名、昵称、网址

**打开**：`src/data/site.config.ts`

这个文件是整站的"身份证"，几乎所有跟"你是谁"有关的东西都在这里。

```ts
title: '回声记录',                          // ← 站名。浏览器标签、页脚、标题后缀都用它
handle: 'YOUR_NAME',                        // ← 你的昵称。页脚 © 和关于页用
tagline: '看番、写码、随手记一点什么',        // ← 首页大标题（有打字机动画）
description: '一个写番剧感想、技术备忘与生活随笔的个人博客。',  // ← 搜索结果里的描述
url: 'https://YOUR_GITHUB_NAME.github.io',  // ← 部署后的真实网址（不带 /blog/）
base: '/blog/',                             // ← 子路径，见下面
since: 2026,                                // ← 建站年份，页脚版权用
footerNote: '慢一点也没关系，路还长。',        // ← 页脚那句小字
issuesUrl: 'https://github.com/YOUR_GITHUB_NAME/blog/issues',  // ← 素材下架通道
```

**改成什么**：

- `title` / `handle` / `tagline` / `description` / `footerNote` —— 引号里的字随便改，**引号不要删**。
- `url` —— 把 `YOUR_GITHUB_NAME` 换成你的 GitHub 用户名。例如 `https://xiaoming.github.io`。
- `issuesUrl` —— 同样把 `YOUR_GITHUB_NAME` 换掉。

**保存后**：首页刷新就能看到新站名。`description` 要等构建才生效（本地预览不一定马上变，正常）。

> ### ⚠️ `base` 是什么
>
> 你的仓库叫 `blog`，所以网站在 `https://用户名.github.io/blog/` 这个**子目录**下，
> 而不是根目录。`base: '/blog/'` 就是在告诉构建工具"所有文件路径都加这个前缀"。
>
> **如果哪天你把仓库改名了**，要同时改两个地方，少一个就整站白屏：
>
> 1. 这里 `src/data/site.config.ts` 的 `base`
> 2. `vite.config.ts` 第 8 行的 `BASE`
>
> 两处必须**一字不差**。

## 2. 换主题色

**打开**：`src/styles/tokens.css`

这是全站**唯一**允许写颜色值的地方。所有组件的颜色都从这里取。
好处是：改一行，全站跟着变，不会漏掉某个角落。

文件里有两套主题，改的时候**两套都要改**，否则切换主题时会看到一个奇怪的配色。

**第一套：Daylight（亮色，默认）** —— 约第 48 行开始：

```css
--bg: #fff8f4; /* 页面底色 */
--bg-soft: #fdefe9; /* 次级底色（输入框、占位块） */
--surface: #ffffff; /* 卡片表面 */
--ink: #211c22; /* 正文颜色 */
--ink-soft: #6b6270; /* 次要文字（日期、说明） */
--line: #eadfd8; /* 描边、分割线 */

--accent: #ff5c8a; /* ★ 主色：按钮、链接、高亮 */
--accent-soft: #ffe3ec; /* 主色的淡版本（选中背景） */
--accent-ink: #ffffff; /* 主色块上的文字颜色 */

--stamp-ink: #c93c56; /* 印章朱色（「既読」章、「本页完」） */
```

**第二套：Neon（暗色）** —— 约第 75 行开始，同名变量再来一遍。

**改成什么**：

只改颜色值，**不要动 `--bg:` 前面的名字**（那是变量的身份证）。

想换主色，只需要改 `--accent` 和 `--accent-soft` 两行，全站立刻变。

**怎么挑颜色**：打开 <https://coolors.co> 或随便一个取色网站，选一个颜色，复制十六进制码（形如 `#ff5c8a`），替换等号后面的值。

**保存后**：全站的主色、按钮、链接、hover 效果一起变。

> **小提醒**：`--accent-ink` 要跟 `--accent` 有足够对比。深主色配白字（`#ffffff`），
> 浅主色配深字（`#211c22`）。配错了按钮上的字会看不清。

## 3. 改导航栏

**打开**：`src/data/site.config.ts`，翻到文件下半部分的 `navItems`（约第 53 行）。

```ts
export const navItems = [
  { key: 'home', label: '首页', path: '/', visible: true },
  { key: 'posts', label: '文章', path: '/posts', visible: true },
  { key: 'favorites', label: '收藏', path: '/favorites', visible: true },
  { key: 'gallery', label: '相册', path: '/gallery', visible: true },
  { key: 'about', label: '关于', path: '/about', visible: true },
  { key: 'tools', label: '工具箱', path: '/tools', visible: false },
  { key: 'now', label: 'Now', path: '/now', visible: false },
  { key: 'credits', label: '素材来源', path: '/credits', visible: false },
]
```

**`visible` 是什么意思**：

- `true` = 导航栏里直接显示
- `false` = **默认隐藏**，但访客可以在「设置面板」（导航栏最右边的齿轮）里自己勾出来

这就是任务书里"自我介绍默认隐藏"的实现方式——不是删掉页面，而是先藏着。

**想做什么**：

| 想做             | 怎么改                                          |
| ---------------- | ----------------------------------------------- |
| 把"工具箱"放出来 | 它的 `visible: false` 改成 `true`               |
| 把"关于"藏起来   | `visible: true` 改成 `false`                    |
| 改显示的名字     | 改 `label` 的引号内容，例如 `'文章'` → `'写字'` |
| 调整顺序         | 把整行 `{ ... }` 剪下来，粘到别的位置           |

> **不要改 `key` 和 `path`**。`key` 是内部标识，`path` 必须跟 `src/router/index.ts` 里的路由对上，
> 改了会跳到空白页。

**保存后**：导航栏立刻更新。藏起来的项在设置面板里能找到。

## 4. 写一篇新文章

这是你最常做的事，所以展开讲。

### 4.1 最省事的方式：用脚本

终端里跑：

```bash
npm run new:post
```

它会依次问你：标题、分类、摘要、标签。
回答完，它自动生成一个 `.md` 文件，放在 `content/posts/2026/` 下，并用编辑器打开。

**不想用它也完全可以**，见下面手动方式。

### 4.2 手动方式：新建一个 .md 文件

**第一步**：在 `content/posts/2026/` 里新建一个文件，文件名用英文和短横线。

```
content/posts/2026/my-first-post.md
```

> 文件名会成为网址的一部分。上面这个文件，网址就是 `/posts/2026/my-first-post`。
> **中文文件名能用，但网址里会变成一长串百分号编码**，不好看也不好友分享。
> 建议取个英文短名，或者直接用 `post-20261126` 这种。

**第二步**：把下面这一整块复制进去，改成你自己的内容。

```markdown
---
title: 文章标题写这里
date: 2026-11-26
category: anime
tags: [芙莉莲, 感想]
summary: 一句话摘要，会显示在文章列表和搜索结果里。建议 20-60 字。
cover: /art/posts/frieren.webp
---

正文从这里开始。

## 一个小标题

正文可以用 **粗体**、_斜体_、`行内代码`。

- 列表项一
- 列表项二

> 引用一段话。

## 另一个小标题

继续写。
```

**第三步**：保存。浏览器会自动刷新，文章已经出现在列表里了。

> **怎么写代码块**：用三个反引号包起来，开头那行写上语言名，就会有语法高亮。
> 例如写 JavaScript 就是三个反引号加 `js`，写 Python 就是三个反引号加 `python`，
> 结尾再用三个反引号闭上。支持的语言有上百种，常见的 `js` / `ts` / `python` / `bash` /
> `html` / `css` / `json` / `yaml` 都没问题。

### 4.3 frontmatter 字段速查

两个 `---` 之间的部分是"元数据"，它不是正文，但决定了文章怎么显示。

| 字段       | 必填 | 说明                                                                                   |
| ---------- | ---- | -------------------------------------------------------------------------------------- |
| `title`    | ✅   | 文章标题                                                                               |
| `date`     | ✅   | 发布日期，格式必须 `2026-11-26`（年-月-日，带前导零）                                  |
| `category` | ✅   | 只能是这四个之一：`anime`（番剧）/ `tech`（技术）/ `essay`（随笔）/ `fragment`（碎片） |
| `summary`  | ✅   | 摘要。列表页、搜索结果、分享卡片都用它                                                 |
| `tags`     | ❌   | 标签数组，写 `[标签1, 标签2]`                                                          |
| `cover`    | ❌   | 封面图路径，见第 10 节。不写就不显示封面                                               |
| `updated`  | ❌   | 最后修改日期。写了会在日期后面显示"更新于 …"                                           |
| `draft`    | ❌   | 写 `true` 就是草稿，**不会出现在网站上**，但文件留在仓库里                             |
| `sample`   | ❌   | 写 `true` 会加一个 SAMPLE 胶带标签。示例内容用，你自己写文章不要加                     |

**分类写错了会怎样**：构建直接报错，并告诉你哪个文件写错了。这是故意的——早报错好过上线才发现。

### 4.4 关于"写完之后"

- 新文章会自动排在最前面（按 `date` 倒序）
- **不需要手动维护任何目录**，`npm run dev` 和 `npm run build` 都会自动扫描 `content/` 目录
- 文章页的"上一篇 / 下一篇"、"第 08 話"、页码、目次条目，全都是自动算的

> **注意打字机字体**：标题用了一套只包含常用字的字体。如果新文章里用了**生僻字**，
> 这个字可能会显示成方框或者默认字体。解决办法见 [第 11 节](#11-换字体) 最后一段。

## 5. 加一条收藏

收藏在「收藏」页展示，分**卡片型**（番剧、游戏）和**条目型**（音乐、书）。

**新建文件**：`content/favorites/作品名.md`（英文短名）

**番剧 / 游戏**（卡片型，有封面、评分、状态）：

```markdown
---
title: 葬送的芙莉莲
type: anime
status: 已看完
score: 9.5
cover: /art/favorites/frieren.webp
link: https://bangumi.tv/subject/400602
---

这里写两三句感想。这段文字会显示在卡片背面。
```

**书 / 音乐**（条目型，没有封面也好看）：

```markdown
---
title: 挪威的森林
type: book
status: 在读
score: 8.0
artist: 村上春树
link: https://book.douban.com/subject/xxxxx/
---

一句话短评。
```

**字段说明**：

| 字段     | 必填 | 说明                                              |
| -------- | ---- | ------------------------------------------------- |
| `title`  | ✅   | 作品名                                            |
| `type`   | ✅   | `anime` / `game` / `book` / `music`               |
| `status` | ✅   | 自由文字：`已看完` / `在看` / `在读` / `已通关`…… |
| `score`  | ❌   | 0-10 的分数，可以带小数。不写就是 0               |
| `cover`  | ❌   | 封面图，卡片型建议写。不写会用一个几何版式封面    |
| `artist` | ❌   | 作者 / 歌手 / 制作方，会显示在标题下面            |
| `link`   | ❌   | 外部链接（Bangumi、豆瓣等），会有一个跳转箭头     |

**保存后**：收藏页立刻多一张卡片，顶部的分类标签计数也会 +1。

## 6. 加一张相册

**第一步**：把图片处理好（详见 [第 9 节](#9-换首页大图) 的图片流程），放到 `public/gallery/`。

建议：宽度 1200，长边不超过 1600，WebP 格式，单张 220 KB 以内。

**第二步**：新建 `content/gallery/照片名.md`：

```markdown
---
title: 书桌一角
date: 2026-07-22
image: /gallery/desk.webp
caption: 一直很乱，但我知道每样东西在哪。收拾整齐反而找不到。
---

书桌一角
```

- `image` 写 `/gallery/文件名.webp`，**开头的斜杠不能少**
- `caption` 是图片下面的说明文字
- 正文那个一行字可以随便写，基本不显示，但文件不能空

**保存后**：相册页多一张图，点开可以看大图。

> ⚠️ **别忘了登记来源**。任何新图片都要在 `public/art/CREDITS.md` 加一行，
> 见 [第 10 节](#10-换某篇文章的封面) 末尾。

## 8. 改关于页 / Now 页

这两页的结构跟文章不太一样，都是**单文件**。

### 关于页

**打开**：`content/about.md`

它的 frontmatter 里是问答和时间线：

```yaml
qa:
  - q: 你是谁？
    a: 一个普通的上网的人。……

timeline:
  - year: '2026'
    text: 第一次自己做网站。
```

- **改一条问答**：改 `q`（问题）和 `a`（回答）后面的文字
- **加一条问答**：复制一整组 `- q:` / `a:`，粘在下面，缩进对齐（`q:` 前面两个空格）
- **删一条**：删掉那一组的两行
- **时间线**：同理，`year` 一定要加引号（否则可能被当成数字）
- **正文部分**（第二个 `---` 之后）也会显示在页面上

> 首页 hero 里那句"关于我"按钮跳的就是这一页。自我介绍默认隐藏的，是导航项，见第 3 节。

### Now 页

**打开**：`content/now.md`

```yaml
---
updated: 2026-11-24
---
```

下面就是普通 Markdown 正文，`##` 小标题 + 列表随便写。
`updated` 改成你今天改它的日期。

## 9. 换首页大图

首页那一大张图是 `public/art/hero.webp`。

### 9.1 如果你已经有一张处理好的 WebP

**直接覆盖** `public/art/hero.webp`。

尺寸要求：**2400 × 1400**（16:9 出头一点），WebP 格式，420 KB 以内。

### 9.2 如果手里是一张原始大图（PNG/JPG）

**第一步**：把原图重命名为 `hero.png`，放进项目的 `raw/` 目录。

**第二步**：跑

```bash
npm run images
```

这个脚本会用 Python + Pillow 把图裁到正确尺寸、转成 WebP、压到预算内。
处理结果自动出现在 `public/art/hero.webp`。

> `npm run images` 一次会处理 `raw/` 里的**所有**图片（`hero.png`、`about.png`、
> `post-*.png`、`fav-*.png`、`gallery-*.png`）。缺哪张就跳过哪张，不会报错。

### 9.3 顺便换分享卡片

微信、QQ、Discord 里分享链接时显示的那张预览图，是单独生成的：

```bash
py scripts/make-og.py
```

默认拿 `hero.webp` 当底图，盖上站名和一句话。想改上面的字，打开
`scripts/make-og.py`，改开头附近的 `TITLE` / `SUBTITLE` / `SEAL` 三个变量。

### 9.4 ⚠️ 换成新图之后必须做的一件事

打开 `public/art/CREDITS.md`，找到 `hero.webp` 那一行，把"出处"和"获取日期"改成新图的。

**为什么要这样**：这是你对版权方的交代，也是万一有人来要求下架时，你能说清图的来源。
`npm run check` 会检查有没有漏登记的图（只警告，不阻断）。

## 10. 换某篇文章的封面

**第一步**：图片放进 `public/art/posts/`，命名随意，例如 `my-post.webp`。
建议尺寸 **1200 × 675**（16:9），160 KB 以内。

**第二步**：打开那篇文章的 `.md`，在 frontmatter 里加一行：

```yaml
cover: /art/posts/my-post.webp
```

开头的 `/` 不能少，路径相对于 `public/`。

**第三步**：在 `public/art/CREDITS.md` 里加一行登记。

### CREDITS.md 每一列填什么

| 列       | 填什么                                                                 |
| -------- | ---------------------------------------------------------------------- |
| 文件名   | `posts/my-post.webp`（在 `art/` 下的相对路径，或 `../gallery/x.webp`） |
| 作品名   | 图的内容，例如「芙莉莲 · 黄昏海岸」                                    |
| 作者     | 能查到就填，查不到填「未标注」                                         |
| 出处     | **原始页面链接**，不是图片直链                                         |
| 许可     | 例如「仅个人展示」「CC BY 4.0」                                        |
| 获取日期 | `2026-11-26`                                                           |
| 级别     | `A` 可自由使用 / `B` 需署名 / `C` 版权归原方、个人展示                 |
| 备注     | 可选                                                                   |

这张表会被自动生成到 `/credits`「素材来源」页。

## 11. 换字体

站上用三套字体，都在 `src/styles/fonts.css` 声明：

| 用途             | 字体               | 变量名           |
| ---------------- | ------------------ | ---------------- |
| 标题、大字号     | 站酷快乐体         | `--font-display` |
| 引文、寄语       | 霞鹜文楷           | `--font-quote`   |
| 数字、日期、代码 | Space Grotesk      | `--font-mono`    |
| 正文             | 系统字体（不下载） | `--font-body`    |

### 只想微调字号 / 行高

**打开**：`src/styles/tokens.css` 最上面的 `:root`。
但注意：字号和行高**不在** `tokens.css` 里，而是在各组件自己的 `<style>` 里。
搜 `font-size` 能找到。

### 想换成别的字体

1. 装包：`npm install @fontsource/你想要的字体`
2. 打开 `scripts/subset-font.py`，把开头的 `FONTS` 清单改成新字体
3. 跑 `npm run fonts` —— 它会扫描全站实际用到的字，裁出子集（几 MB → 几百 KB）
4. 打开 `src/styles/fonts.css`，改 `@font-face` 里的 `font-family` 名字和路径
5. 打开 `src/styles/tokens.css`，把 `--font-display` 等变量改成新名字

> 这几步略微进阶。如果只是想换个氛围，**更简单的做法是改字号和字重**，
> 效果差别比换字体更大，风险却小得多。

### 生僻字显示成方框？

因为字体只包含"当时站点里出现过的字"。新加了生僻字之后：

```bash
npm run fonts
```

重新扫描一遍就有了。

## 12. 上传前的安全检查

你提过一个要求：**不要把隐私密钥传上 GitHub**。项目内置了四道防线：

### 12.1 自动扫描（最常用）

```bash
npm run check:secrets
```

它会扫描所有会被提交的文件，找这些东西：

- 各种真实密钥格式（GitHub token、AWS 密钥、OpenAI/Claude key、Google API key、JWT、带密码的数据库连接串……）
- 危险文件名：`.env`、`*.pem`、`*.key`、`id_rsa`、`.npmrc`、`.netrc`、云服务凭证文件

**通过了**会打印：`[密钥扫描] 通过，检查了 N 个文件。`

**没通过**会告诉你哪个文件第几行、命中了什么类型，并把密钥**打码显示**（只露头尾几个字符）。
照着提示把它删掉或换成占位符即可。

### 12.2 提交时自动拦截

项目里有一个 git 钩子 `.githooks/pre-commit`，每次 `git commit` 之前自动跑扫描。
有密钥就**直接拒绝提交**。

**只需要激活一次**（每个新克隆的仓库都要做一次）：

```bash
git config core.hooksPath .githooks
```

### 12.3 GitHub 上再查一遍

`.github/workflows/deploy.yml` 里有一个独立步骤跑 `npm run check:secrets`。
万一本地钩子被绕过，云端会拦住，部署不会成功。

### 12.4 万一真的提交了怎么办

**立刻作废那把密钥**，这比什么都重要：

1. GitHub token → 去 Settings → Developer settings → 撤销
2. 云服务密钥 → 去对应控制台删掉 / 轮换
3. 改完之后，把文件从 Git 历史里清掉（只删文件不够，历史里还留着）

> 如果只是**本地**的 `.env.local` 文件被写了密钥，那没问题——它在 `.gitignore` 里，
> 永远不会被提交。这个仓库本来也不需要任何密钥。

### 12.5 个别文件确实要放密钥字样怎么办

在那一行末尾加注释：

```js
const example = 'sk-xxxxxxxx' // secret-scan-ignore
```

扫描器会跳过这一行。**只在你确定那是假例子时用**。

## 13. 出错了怎么办

### 本地预览打不开

1. 终端里有没有红字？先看红字。
2. 端口被占用：终端里按 `Ctrl + C`，重新 `npm run dev`。
3. 还是不行：删掉 `node_modules`，跑 `npm install`，再试。

### 文章不出现

- `category` 是不是四个之一？写错会直接报错，不会静默消失。
- `draft: true` 了吗？草稿不上站。
- 文件是不是放在 `content/posts/2026/` 下（或者当年的年份目录）？
- 文件名是不是 `.md` 结尾？

### 图片不显示

- 路径开头有没有 `/`？应该是 `/art/posts/xxx.webp`，不是 `art/posts/xxx.webp`。
- 文件真的在 `public/` 下吗？`public/art/posts/xxx.webp` 对应网址 `/art/posts/xxx.webp`。
- 大小写对不对？Linux 上（GitHub 构建时）**大小写敏感**，`Hero.webp` 和 `hero.webp` 是两个文件。

### 整站白屏（部署后）

九成是 `base` 配错了。检查 `src/data/site.config.ts` 的 `base` 和 `vite.config.ts` 的 `BASE`
是不是都是 `'/仓库名/'`。

### `npm run check` 里某一项失败

| 报错开头                  | 意思                    | 怎么办                                          |
| ------------------------- | ----------------------- | ----------------------------------------------- |
| `[密钥扫描]`              | 发现疑似密钥            | 见第 12 节                                      |
| `error TS`                | TypeScript 类型错误     | 一般是你改了 `.ts` 文件。看报错里的文件名和行号 |
| `✖ N problems`            | ESLint 代码风格问题     | 大部分是没用到的变量。删掉即可                  |
| `Code style issues found` | Prettier 格式问题       | 跑 `npm run format` 自动修好                    |
| `[资源校验]`              | 图片缺失 / 没登记来源   | 看提示里的文件名                                |
| `[内容错误]`              | 文章 frontmatter 写错了 | 提示里有具体文件和建议值                        |

**万能解**：跑 `npm run format`，能自动修掉一半的问题。

```
content/                  ← 你写的东西全在这（Markdown）
├── posts/2026/           ← 文章，按年份分目录
├── favorites/            ← 收藏
├── gallery/              ← 相册
├── tools/                ← 工具箱
├── about.md              ← 关于页（问答 + 时间线）
└── now.md                ← Now 页

public/                   ← 图片、图标（原样发布，不经过处理）
├── art/
│   ├── hero.webp         ← 首页大图
│   ├── about.webp        ← 关于页插画
│   ├── favicon.svg       ← 浏览器标签页图标
│   ├── og-default.jpg    ← 分享卡片
│   ├── posts/            ← 文章封面
│   ├── favorites/        ← 收藏封面
│   └── CREDITS.md        ← ★ 素材来源登记表
└── gallery/              ← 相册图片

src/
├── data/site.config.ts   ← ★ 站名、昵称、导航、功能开关
├── styles/tokens.css     ← ★ 颜色、圆角、动效时长
├── styles/fonts.css      ← 字体声明
```
