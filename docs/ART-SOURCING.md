# 素材获取指南

> 去哪儿找图、什么样的图能用、怎么处理、怎么登记。
>
> **重要前提**：本站是个人非商业站点。这一页讨论的是"怎么做"，不是"这样做一定合法"。
> 版权是严肃的事，最终判断请自行负责。

---

## 一、素材分级

每张图在 `public/art/CREDITS.md` 里必须标一个级别：

| 级别  | 含义                             | 典型来源                                              |
| ----- | -------------------------------- | ----------------------------------------------------- |
| **A** | 明确可商用 / 可自由使用          | CC0、Unsplash、Pexels、いらすとや（有条件）、公共领域 |
| **B** | 可用但**必须署名**               | CC BY、CC BY-SA                                       |
| **C** | 版权归原权利方，仅个人非商业展示 | 同人图、官方图二次传播、来源不明                      |

**本站目前的插画全部是 C 级。**

这不是疏忽，是现实：二次元插画绝大多数是同人创作或官方美术，版权归原作者或制作委员会，
没有任何"免费商用"的授权。个人博客非商业展示是一种常见做法，但不等于合法。

**C 级必须做到两件事**：

1. **逐张登记来源**（原始页面链接，不是图片直链）
2. **提供下架通道**（`/credits` 页 + 仓库 Issues）

## 二、去哪儿找

### 二次元插画

| 站点                                | 特点                                           | 注意事项                                                                  |
| ----------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------- |
| **safebooru** <br/>`safebooru.org`  | 带标签检索，全站只收安全级内容，有原图尺寸信息 | 图片本身是同人或官方图，版权 C 级。登记时记 `post id`                     |
| **Pixiv**                           | 质量最高的二次元插画                           | **任务书红线：不抓取**。想用必须逐张联系作者取得授权                      |
| **Danbooru / Gelbooru**             | 图库大                                         | 含不适合的内容，需要严格过滤；版权同样 C 级                               |
| **いらすとや** <br/>`irasutoya.com` | 日式扁平插画，风格统一                         | 免费，但有使用条件（大量使用、商用有限制）。级别填 A 或 B，看它的最新条款 |

### 通用高质量图（可到 A 级）

| 站点                  | 授权                         | 适合                   |
| --------------------- | ---------------------------- | ---------------------- |
| **Unsplash**          | Unsplash License（近似 CC0） | 风景、氛围、城市、桌面 |
| **Pexels**            | Pexels License               | 同上，二次元风格较少   |
| **Pixabay**           | Pixabay License              | 混合，注意筛选         |
| **Wikimedia Commons** | 逐张不同（多为 CC BY-SA）    | 需要仔细看每张的授权   |

**如果你不确定，就用 A 级来源做风景/氛围图，C 级只用在明显"同人感想"的文章封面上。**
这样风险最低。

## 三、尺寸与体积预算

| 用途       | 路径                          | 尺寸                  | 上限   |
| ---------- | ----------------------------- | --------------------- | ------ |
| 首页主视觉 | `public/art/hero.webp`        | 2400 × 1400           | 420 KB |
| 关于页插画 | `public/art/about.webp`       | 1200 × 1200           | 200 KB |
| 文章封面   | `public/art/posts/*.webp`     | 1200 × 675（16:9）    | 160 KB |
| 收藏封面   | `public/art/favorites/*.webp` | 500 × 700（5:7 竖版） | 90 KB  |
| 相册       | `public/gallery/*.webp`       | 长边 ≤ 1600           | 220 KB |
| 分享卡片   | `public/art/og-*.jpg`         | 1200 × 630            | —      |
| 站点图标   | `public/art/favicon.svg`      | 矢量                  | —      |

**为什么这么严**：图片是页面变慢的第一大原因。一张 8 MB 的 PNG 能让移动端首屏多等十几秒。

## 四、处理流程

### 方式 A：脚本处理（推荐）

**第一步**：下载原图，重命名成下面这些名字之一，放进 `raw/`：

| raw 里的文件名    | 变成                               |
| ----------------- | ---------------------------------- |
| `hero.png`        | `public/art/hero.webp`             |
| `about.png`       | `public/art/about.webp`            |
| `post-<名字>.png` | `public/art/posts/<名字>.webp`     |
| `fav-<名字>.png`  | `public/art/favorites/<名字>.webp` |
| `gallery-<N>.png` | `public/gallery/<名字>.webp`       |

**第二步**：

```bash
npm run images
```

脚本会：按目标尺寸居中裁剪 → 转 WebP → 如果超过体积预算，自动降质量重压（最多试 3 次）。

**想加一张新图**：打开 `scripts/optimize-images.py`，在 `TASKS` 列表里加一行：

```python
("post-my-new-post.png", ART / "posts" / "my-new-post.webp", 1200, 675, "crop", 80),
```

格式是 `(raw 里的文件名, 输出路径, 宽, 高, 裁剪方式, 质量)`。

### 方式 B：在线工具

不想碰脚本的话：<https://squoosh.app>

1. 拖入图片
2. 右边选 **WebP**，质量调到 80 左右
3. 左下角 **Resize** 填目标尺寸（勾选保持比例或直接裁）
4. 下载，放进 `public/` 对应目录

免费、在浏览器里跑、不上传服务器。

### 方式 C：已经是 WebP 且尺寸对了

直接放进 `public/` 对应目录，覆盖同名文件即可。

## 五、登记来源（必须做）

**打开**：`public/art/CREDITS.md`

加一行，格式跟表头对齐：

```markdown
| `posts/my-new-post.webp` | 芙莉莲 · 黄昏海岸 | 未标注 | https://safebooru.org/index.php?page=post&s=view&id=7272265 | 仅个人展示 | 2026-11-26 | C | 同人插画 |
```

**关键几点**：

1. **文件名列**：三种写法都认
   - `hero.webp` → 默认当作 `public/art/hero.webp`
   - `posts/x.webp` → `public/art/posts/x.webp`
   - `../gallery/x.webp` → `public/gallery/x.webp`

2. **出处列**：填**原始页面链接**，不是 `https://img.safebooru.org/images/xx/yy.jpg` 这种直链。
   原始页面能追溯到作者和作品，直链过几个月就失效了。

3. **能查到作者就填**。查不到填「未标注」，不要编。

4. **获取日期**：你下载的日期。这在以后想追溯时很有用。

**保存后**：跑一下

```bash
npm run check:assets
```

它会告诉你哪张图用了但没登记。只警告不阻断（因为版权本就是个灰色地带，不至于卡死构建），
但**别忽略那个警告**。

## 六、AI 生成的图

**可以用**，但要登记清楚：

```markdown
| `posts/x.webp` | 抽象几何 | AI 生成（Stable Diffusion） | 本地生成 | 无版权主张 | 2026-11-26 | A | 自用 |
```

**注意**：

- 主流生成工具的条款各不相同，商用限制也不一样，用之前看一眼
- AI 图**不要标成 A 级然后声称"CC0"**，那是不诚实的
- 涉及特定作品的角色（"画一个芙莉莲"）仍然是 C 级——角色形象有独立的版权

## 七、绝对不要做的

| 不要                         | 为什么                                 |
| ---------------------------- | -------------------------------------- |
| 从 Pixiv / X / 微博 批量抓图 | 任务书红线；也是对创作者最直接的伤害   |
| 把 C 级图用于任何商业用途    | 这是真的会被告的                       |
| 用来源不明的图还不登记       | 万一被找上门，你连"这是哪来的"都说不清 |
| 声称别人的图是自己的         | —                                      |
| 把官方的番剧截图当"插画"     | 那是另一类版权，动漫截图的使用限制更严 |

## 八、万一被要求下架

**态度**：立刻照做，不要争辩，不要装死。

**流程**：

1. 删掉那张图（或者换成别的）
2. 删掉 `CREDITS.md` 里对应那行
3. 提交、推送
4. 在 Issue 里回复一句"已下架"

**为什么这很重要**：你是个人站，对方是权利方。姿态好一点，事情就结束了；
姿态不好，可能升级成正式的侵权投诉，那时候 GitHub 会直接关掉你的仓库。

`/credits` 页面上那句"如你是权利方且不希望作品出现在这里，请通过仓库 Issues 联系下架"
就是为了这个——**表明你不是在装看不见**。

## 九、更好的长期方案

如果这个站要长期做下去，C 级素材始终是个隐患。几条路：

1. **慢慢换成 A/B 级**。风景、氛围、桌面、街景这些题材，Unsplash 上有大量高质量免费图。
   二次元风格的文章封面，考虑用**抽象几何 + 排版**代替具体插画（本站的收藏页在没有封面时
   就是这么做的，效果不差）。
2. **自己画**。哪怕是简单的涂鸦，也比用别人的图踏实。
3. **委托约稿**。几百块能买到一张明确授权的原创图，长期站值得这个投入。
4. **CC0 素材站**：<https://www.pexels.com>、<https://unsplash.com>、
   <https://commons.wikimedia.org>（逐张看授权）。

**本站已经做的妥协**：所有 C 级图都只是氛围/场景，没有把别人的原创角色图当作站点主视觉的核心。
首页那张是风景插画，不是角色图。
